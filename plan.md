# subagent-mcp — plan

An MCP server whose headline tool, `launch_subagent`, collapses the whole
"spawn a coding CLI in a tmux window" ritual into one call.

Sibling of `basic-fns-mcp` and `basic-memory` in `~/ATLAS-GROUP/`. Same shape:
Python + `fastmcp`, `src/` layout, stdio for ATLAS, streamable-HTTP for poking.

---

## 1. The problem

Today launching an agent is ~6 shell steps with three timing landmines:

```bash
tmux new-window -t atlas -n fix-738 -c /home/garlan/git/atlas/atlas-ui-3
tmux send-keys -t atlas:fix-738 'dclaude' Enter
sleep 8                                     # or the prompt gets eaten
printf '%s' "$PROMPT" | tmux load-buffer -
tmux paste-buffer -t atlas:fix-738 -d
sleep 5                                     # or Enter submits a partial prompt
tmux send-keys -t atlas:fix-738 Enter
```

Every step is a place to lose a prompt, and the failure mode is silent — a
truncated prompt looks like a working agent.

## 2. What is actually unnecessary

Verified against the installed CLIs and tmux on this host (2026-08-08):

| Ceremony | Verdict |
|---|---|
| `sleep 8` after launch | **Unneeded.** Only exists because the prompt is typed *after* the TUI starts. Seed it at launch instead. |
| `load-buffer` / `paste-buffer` / separate `Enter` | **Unneeded for launch.** Both CLIs take the prompt on argv. Still needed for *follow-up* messages to a live agent — that's the one place the dance survives. |
| `sleep 5` before `Enter` | Same — gone with the paste. |
| `send-keys -l` escaping worries | Gone. Nothing goes through key parsing. |
| `dclaude` | **Actively broken from a server.** It is a shell *alias* (`.bashrc:175`, `.profile:31`), invisible to any non-interactive shell. Expand it to `claude --dangerously-skip-permissions`. |
| `tmux new-window -t <sess>` | Fails outright if the session doesn't exist. The server should ensure-or-create. |
| Targeting windows by `sess:name` | Fragile — names collide, windows renumber. Capture the **pane id** at launch instead. |

Confirmed CLI surfaces:

- `claude [options] [prompt]` — positional prompt, interactive by default
  (`-p/--print` is the opt-*out*). Also `--model`, `--agent`,
  `--permission-mode`, `--session-id`, `--add-dir`.
- `opencode --prompt "..."` — seeds the TUI. (`opencode run` is the
  headless/non-TUI path; not what we want here.) Also `-m/--model`,
  `--agent`, `--auto`, `--variant`.

Confirmed tmux behavior (tested on a throwaway `-L plantest` socket):

- `new-window -P -F '#{pane_id}'` prints a stable pane id (`%1`) — use it as
  the handle for every later operation.
- **`new-window` does *not* exec an argv vector.** Extra arguments are joined
  into one string and handed to the shell; a multi-arg call created a window
  that died instantly. So there is exactly one layer of shell quoting to get
  right, which is the argument for §4.

## 4. Launch mechanism — the generated wrapper

Do **not** try to cram the prompt into the tmux command string. For each run,
create `<runs_root>/<ts>-<slug>/` containing:

- `prompt.md` — the full prompt, verbatim, no escaping anywhere
- `meta.json` — cwd, cli, model, session, window, pane id, argv, start time
- `run.sh` — generated, `chmod +x`, arguments built with `shlex.quote`
- `out.log` — pane output, if logging is enabled

```sh
#!/usr/bin/env bash
# generated by subagent-mcp — <run-id>
cd '<cwd>' || exit 1
claude --dangerously-skip-permissions --model 'opus' "$(cat '<run>/prompt.md')"
code=$?
printf '\n[subagent-mcp] exited %d — run dir: %s\n' "$code" '<run>'
exec "${SHELL:-/bin/bash}" -i     # keep the pane alive to inspect
```

Then a single tmux call:

```
tmux new-window -t <session> -n <window> -c <cwd> -P -F '#{pane_id}' '<run>/run.sh'
```

Why this wins: one quoting layer instead of three, prompts of any size with any
characters, the exact invocation is on disk and re-runnable by hand, the pane
survives a crash so the error is still readable, and `--dry-run` can return
`run.sh` without executing anything.

Prompt-length note: `claude` takes the prompt on argv, so a giant prompt still
rides `ARG_MAX` (~2MB, fine). If `prompt_file` is passed and
`prompt_mode="pointer"`, seed a short bootstrap instead — *"Read the file at
`<path>` and execute all instructions in it."* — which is the pattern already in
use for long tasks.

## 5. Tools

### `launch_subagent` — the one that matters

| Param | Default | Notes |
|---|---|---|
| `prompt` | — | required unless `prompt_file` |
| `prompt_file` | — | alternative source; see `prompt_mode` |
| `prompt_mode` | `"inline"` | `"inline"` \| `"pointer"` (bootstrap-read-the-file) |
| `cwd` | config root | repo to work in; must exist and be a dir |
| `cli` | `"claude"` | `"claude"` \| `"opencode"` |
| `session` | basename of `cwd` | tmux session; **created if missing** |
| `window` | slug of `task` or first prompt line | deduped `-2`, `-3`, … |
| `task` | — | short human label; feeds the window name |
| `model` | — | passthrough `--model` / `-m` |
| `agent` | — | passthrough `--agent` (either CLI) |
| `dangerous` | `true` | `--dangerously-skip-permissions` / `--auto`. Explicit, not hidden in an alias. |
| `extra_args` | `[]` | escape hatch, appended verbatim |
| `settle_seconds` | `3` | wait, then capture the pane so the caller sees it actually started |
| `dry_run` | `false` | return `run.sh` + argv, launch nothing |

Returns JSON: `run_id`, `pane_id`, `target` (`sess:win`), `session`, `window`,
`cwd`, `cli`, `run_dir`, `alive`, `initial_output` (last ~40 lines after
settling), and `hint` — the literal `tmux attach -t sess:win` string to paste.

The `settle_seconds` capture is the point of the whole design: the call comes
back with evidence the agent is running, instead of a blind fire-and-hope.

### Companions (small, and each one replaces a command you type today)

- `check_subagent(handle, lines=100)` → `capture-pane -p -S -<lines>`, plus
  `alive` and `pane_current_command`. Replaces the manual `capture-pane`.
- `list_subagents(session=None)` → every window this server launched (from
  `meta.json`) reconciled against live tmux state: run_id, target, cli, cwd,
  task, alive, age.
- `send_to_subagent(handle, text, submit=true)` → follow-up message to a live
  agent. **This is where paste-buffer stays**, ceremony and all:
  `load-buffer` → `paste-buffer -d` → brief settle → `send-keys Enter`.
- `stop_subagent(handle, kill_window=false)` → `send-keys C-c`, or kill.

`handle` accepts a pane id, a `sess:win` target, or a run_id.

## 6. Safety

This is remote code execution with permission checks off, by design — same
posture as `basic_fns --dangerous`. Trusted single-user dev box only.

Guards worth having anyway, because they catch mistakes rather than attackers:

- `--root` allowlist of parent dirs for `cwd` (default: `~/git`, `~/ATLAS-GROUP`);
  `--any-cwd` to disable.
- `--max-concurrent` (default 12) counting live launched windows; refuse past it
  rather than fork-bombing the box with TUIs.
- Refuse a `cwd` that isn't a directory; refuse an empty prompt.
- Never `attach` — windows are always detached. The server must not fight the
  user for the terminal.
- `--cli-allowlist claude,opencode`; `extra_args` never goes through a shell
  unquoted.

## 8. Testing

- `tmuxio` takes the socket name, so tests run on a private `-L subagent-test`
  server and `kill-server` in teardown. No risk to the 7 real sessions.
- A fake CLI (`tests/bin/claude`) that echoes its argv to a file and sleeps
  proves prompt delivery exactly — including that a prompt with quotes,
  newlines, `$(…)`, and backticks arrives byte-identical.
- `dry_run` snapshots of generated `run.sh` for both CLIs.
- Failure paths: missing session, nonexistent cwd, window-name collision,
  concurrency cap, immediately-exiting CLI (window should survive via the
  wrapper's trailing `exec $SHELL`).

## 10. Open questions

- **Follow-up settle time.** `send_to_subagent` still needs a paste→pause→Enter
  gap. Fixed `sleep`, or poll `capture-pane` until the pasted tail appears?
  Polling is strictly better but needs a stable marker; start with a 1.5s sleep
  and revisit if it drops input.
- **Prompt default: inline or pointer?** Inline is simpler and verified to work
  on argv. Pointer keeps the tmux/argv line tiny and matches the existing habit
  for long tasks. Proposal: inline by default, auto-switch to pointer above
  ~16KB.
- **Session naming.** Deriving from `basename(cwd)` gives `atlas-ui-3`, but the
  live session is named `atlas`. Ship an optional `--session-map` (cwd prefix →
  session name) so existing sessions get reused instead of a near-duplicate
  appearing next to them.
- **Should `launch_subagent` ever block until done?** A `wait_seconds` /
  `wait_for_idle` option is tempting, but agents run for many minutes; keep it
  fire-and-inspect, and let the caller poll `check_subagent`.
- **`runs/` retention.** Prompts accumulate. Prune runs older than N days on
  startup, or leave it manual?

# PHASE 2 — review findings

Phase 1 is implemented and works: 12/12 tests pass, the stdio server lists all
five tools, and the `subagent` entry is live in `atlas-ui-3/config/mcp.json`.

Two premises were confirmed against the real tooling rather than assumed:

- **A1 holds.** A real `claude` launched through the generated wrapper into
  `~/ATLAS-GROUP/atlas-ui-3` seeded the TUI from the positional prompt,
  submitted it, and answered. The design works end to end.
- **The `"$(cat prompt.md)"` inline path is safe.** A prompt containing
  `"quotes"`, `'quotes'`, backticks, `$(id -u)`, `$HOME`, `${PATH}`, tabs,
  backslashes, `*`, `|`, and `; rm -rf /` arrived at the CLI byte-identical.
  No shell re-expansion.

Also verified: sync tools run in a fastmcp worker threadpool, so
`settle_seconds` does not block the event loop — but that makes the concurrency
issues in P2-6 real rather than theoretical.

## P2-1 — `stop_subagent(kill_window=True)` can kill a bystander window

`server.py:390` targets `f"{run.session}:{run.window}"` — a stale *name* — while
holding `run.pane_id`. tmux falls back to prefix matching when there is no exact
hit.

Reproduced: with windows `keepme` and `win1x` in session `abc`,
`tmux kill-window -t abc:win1` killed **`win1x`**, rc=0, no error. A window
renamed by the CLI, or a run deduped to `fixit-2`, destroys an unrelated window.
The `atlas` session has 8 live windows of exposure.

**Fix:** `tm.kill_window(run.pane_id)`. tmux resolves `%id` to its window.

## P2-2 — fuzzy session targeting puts windows in the wrong session

`tmuxio.py:54, 62, 71, 93` pass bare session names.

Reproduced: with only `atlas-group` alive, `has-session -t atlas` returns **0**,
and `new-window -t atlas` created the window inside **`atlas-group`**. So a
session whose name is a prefix of an existing one can never be created — the
window silently joins the wrong session. Reachable today given the live sessions
(`atlas`, `atlas-group`, `garland-industries`, `AIMS-simulation`, …).

**Fix:** exact-match `=` prefix on every target — `-t "=name"` for sessions,
`-t "=sess:=win"` for windows. Both forms verified working.

## P2-3 — the settle-capture returns a false green on the trust dialog

Launching into a directory `claude` has not seen shows *"Quick safety check: Is
this a project you created or one you trust?"* and waits on a modal forever.
`launch_subagent` returned `alive: true`, `current_command: node`, and a
healthy-looking pane. `--dangerously-skip-permissions` does **not** bypass it —
tested both ways.

This fires on every fresh git worktree, which the worktree flow creates
constantly. Catching exactly this is the reason the settle-capture exists.

**Fix:** scan `initial_output` for known blocking patterns (trust dialog, login
prompt, model picker) and return `blocked: true` with the matched reason, so the
caller sees a red instead of a green.

## P2-4 — recycled pane ids match dead runs

tmux restarts pane numbering at `%0` per server (verified). `meta.json` files
live forever, so after a tmux restart old runs match new panes:
`list_subagents` reports corpses as alive, `_active_count` consumes the
`max_concurrent` budget, and `send_to_subagent` by `run_id` can type into an
unrelated pane.

**Fix:** record `#{pane_pid}` (or session+window) at launch and verify it still
matches before trusting a stored pane id. Pairs with the `runs/` retention
question in §10.

## P2-5 — `_active_count` is N+1 subprocesses

`server.py:86` — `pane_alive` shells out to `list_panes()` once per historical
run, so launch latency grows with the size of `runs/`.

**Fix:** one `list_panes()` into a set, then membership tests.

## P2-6 — `send_to_subagent` is untested and races on the global buffer

It is the one place the paste-buffer ceremony survives — the part most likely to
drop input — and nothing covers it. It also uses the unnamed global tmux buffer,
so two concurrent sends can clobber each other.

**Fix:** `load-buffer -b <run_id>` / `paste-buffer -b <run_id>`, plus the
fake-CLI test the plan called for in §8.

## P2-7 — smaller items

- `_read_prompt` **concatenates** `prompt` and `prompt_file` when both are
  given, though the Field description says "alternative to prompt". It also
  silently `.strip()`s the result.
- `pointer_threshold_bytes` is defined in `config.py` and never read — the 16KB
  auto-pointer switch from §10 was not built. Either wire it up or drop the field.
- `wrapper_command()` substitutes the prompt by token equality, so an
  `extra_args` entry identical to the `$(cat …)` string would be mangled.
  Theoretical, but a marker sentinel is cheaper than the bug.
- `_tip()` has unreachable code after the `launch_subagent` early return.
- `Tmux._run`'s `timeout` raises `TimeoutExpired`, which escapes as something
  other than `ToolError`.
- `ensure_session` leaves a stray shell at window 0 when it creates a session.
- No `.gitignore` and no `git init`, unlike the sibling repos; `.pytest_cache`
  is loose in the tree.

## Order of work

1. **P2-1** and **P2-2** first — they are the two that can damage windows and
   sessions you care about, and both are a few lines.
2. **P2-3** — turns the headline tool's success signal honest.
3. **P2-5**, then **P2-4** and **P2-6**.
4. **P2-7** as cleanup.

# PHASE 3 — retention and mid-run blocking

## P3-1 — blocked detection only ran at launch

`_detect_blocked_output` was called once, in `launch_subagent`, against the
settle-capture. That catches the startup trust dialog (P2-3) but nothing after
it: a permission modal appearing twenty minutes into a run left
`check_subagent` reporting `alive: true` with the modal sitting in `output`,
where only a human reading the pane would notice it.

Done:

- `check_subagent` runs the detector on every capture and returns
  `blocked` / `blocked_reason` alongside `output`. Both early-return shapes
  (closed pane, and `stop_subagent`'s fallback) carry the same keys so the
  response shape never varies.
- Echo suppression needs the prompt, which `check_subagent` does not receive.
  `_run_prompt_text(run)` reads it back from the run dir's `prompt.md` — every
  launch persists it, and a missing file just means no suppression.
- Three permission-modal patterns added, all verbatim CLI chrome
  (`Do you want to proceed|make this edit|create`, `Yes, and don't ask again`,
  `No, and tell Claude what to do differently`) rather than anything an agent
  would narrate on its own.

## P3-2 — `runs/` grew without bound

Nothing ever deleted a run directory, and `list_subagents` walks all of them,
so the listing got slower forever. Retention is now policy, not housekeeping:

- `prune_runs(runs_root, keep_max, max_age_days, protect)` in `runs.py`.
  Both limits count *every* run on disk — a live subagent occupies a slot — but
  only unprotected runs are deleted. A dir is removed only if it sits directly
  under `runs_root` and holds a `meta.json`, so a stray directory survives.
- `launch_subagent` calls it after the settle capture: it is the only tool that
  grows `runs/`, and the live-pane set is already in hand to build `protect`.
  The count comes back as `pruned_runs`.
- Defaults `runs_keep_max=200` / `runs_max_age_days=14`, each disabled by 0,
  overridable via `--runs-keep-max` / `--runs-max-age-days` or
  `SUBAGENT_RUNS_KEEP_MAX` / `SUBAGENT_RUNS_MAX_AGE_DAYS`.
